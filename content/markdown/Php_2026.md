# Architecture Technique : Le Standard ADI (Application / Domaine / Infrastructure)

Ce document définit la structure et les règles architecturales de l'application. En 2026, pour garantir la maintenabilité, la testabilité et la compatibilité avec les runtimes modernes (comme FrankenPHP en mode Worker), nous suivons strictement l'architecture **ADI**.

---

## 1. La Règle d'Or des Dépendances

Le principe fondamental de cette architecture est le **sens unique des dépendances**. Le code des couches supérieures ne doit jamais avoir connaissance du code des couches inférieures.

$$\text{Infrastructure} \longrightarrow \text{Application} \longrightarrow \text{Domaine}$$

* **L'Infrastructure** a le droit de connaître l'Application et le Domaine.
* **L'Application** a le droit de connaître le Domaine.
* **Le Domaine** ne connaît personne.

Si cette règle est transgressée, l'analyse statique (PHPStan / ArchUnit) bloquera la CI/CD.

---

## 2. Structure des Dossiers

L'arbre ci-dessous montre l'organisation d'un module ou contexte métier (ex: `User`) :

```text
src/
└── User/
    ├── Domain/         # Le Cerveau (Métier pur, 0 dépendance)
    │   ├── Model/      # Entités, Value Objects
    │   └── Repository/ # Interfaces / Contrats de stockage
    │
    ├── Application/    # L'Orchestrateur (Cas d'usage)
    │   ├── UseCase/    # Services d'écriture (Commandes / Actions)
    │   └── Selector/   # Services de lecture optimisés (Queries)
    │
    └── Infrastructure/ # Les Mains (Framework, SQL, HTTP, CLI)
        ├── Controller/ # Points d'entrée HTTP
        ├── Persistence/# Implémentations SQL (PDO, ORM)
        └── Gateway/    # Clients API externes, Mailers
```

---

## 3. Les Couches en Détail

### 🟢 D : Le Domaine (Domain)

C'est le cœur de l'application. Il contient la logique métier pure et les règles de gestion.

**Contrainte :** Aucun framework, aucun ORM, aucune bibliothèque externe. Uniquement du PHP natif typé de manière stricte (`declare(strict_types=1);`).

**Contenu :** Les entités (objets avec identifiant), les Value Objects (objets immuables définis par leurs attributs), et les interfaces des dépôts (Repositories).

### 🔵 A : L'Application

Cette couche orchestre les scénarios de l'application sans savoir comment les données sont affichées ou stockées techniquement. Elle se découpe de manière explicite :

- **Les Use Cases :** Classes uniques dédiées à une action d'écriture (ex: `RegisterUserUseCase`). Ils reçoivent des structures de données simples (DTO), valident le scénario, manipulent le Domaine et déclenchent la sauvegarde via les interfaces.
- **Les Selectors :** Classes dédiées exclusivement à la lecture de données. Contrairement aux Use Cases, ils peuvent contourner le modèle du Domaine pour faire des requêtes de lecture directes et ultra-performantes, évitant ainsi le piège des objets lourds en mémoire.

### 🔴 I : L'Infrastructure

C'est la couche technique, interchangeable et dépendante du monde extérieur.

**Contenu :** Les contrôleurs HTTP, les commandes de console (CLI), la configuration du framework, et les implémentations concrètes des interfaces du Domaine (ex: `SqlUserRepository` qui écrit les requêtes SQL réelles).

**Attention (Mode Worker) :** Le code dans l'infrastructure doit être **stateless**. Pas de propriétés de classes statiques mutables, car l'application reste en mémoire d'une requête à l'autre sous FrankenPHP.

## 4. Exemple Concret d'Implémentation

### Domaine : Le Contrat

Le domaine définit le besoin métier sous forme d'interface.

```php
<?php
// src/User/Domain/Repository/UserRepositoryInterface.php
declare(strict_types=1);

namespace App\User\Domain\Repository;

use App\User\Domain\Model\User;

interface UserRepositoryInterface
{
    public function save(User $user): void;
    public function findByEmail(string $email): ?User;
}
```

### Application : L'Orchestration

L'application utilise l'interface du domaine par injection de dépendance.

```php
<?php
// src/User/Application/UseCase/RegisterUserUseCase.php
declare(strict_types=1);

namespace App\User\Application\UseCase;

use App\User\Domain\Model\User;
use App\User\Domain\Repository\UserRepositoryInterface;

final readonly class RegisterUserUseCase
{
    public function __construct(
        private UserRepositoryInterface $userRepository
    ) {}

    public function execute(string $email, string $plainPassword): void
    {
        if ($this->userRepository->findByEmail($email) !== null) {
            throw new \DomainException("Cet email est déjà enregistré.");
        }

        $hashedPassword = password_hash($plainPassword, PASSWORD_ARGON2ID);
        $user = new User(uniqid('usr_'), $email, $hashedPassword);

        $this->userRepository->save($user);
    }
}
```

### Infrastructure : Le Code Réel

L'infrastructure réalise l'action technique en implémentant le contrat du domaine.

```php
<?php
// src/User/Infrastructure/Persistence/PdoUserRepository.php
declare(strict_types=1);

namespace App\User\Infrastructure\Persistence;

use App\User\Domain\Model\User;
use App\User\Domain\Repository\UserRepositoryInterface;
use PDO;

final readonly class PdoUserRepository implements UserRepositoryInterface
{
    public function __construct(private PDO $pdo) {}

    public function save(User $user): void
    {
        $stmt = $this->pdo->prepare("INSERT INTO users (id, email, password) VALUES (:id, :email, :password)");
        $stmt->execute([
            'id' => $user->getId(),
            'email' => $user->getEmail(),
            'password' => $user->getPasswordHash(),
        ]);
    }

    public function findByEmail(string $email): ?User
    {
        // Logique SQL pour récupérer l'utilisateur ou retourner null
        return null;
    }
}
```

## 5. Outillage & Validation de la Structure

Pour éviter l'érosion de cette architecture au fil du temps, deux outils sont obligatoires sur le projet :

- **PHPStan (Level 9) :** Strictement configuré pour interdire les types implicites ou magiques.
- **Pest Arch / ArchUnit :** Un test unitaire automatique valide qu'aucune classe du dossier `Domain` n'importe un namespace contenant `Infrastructure`.
